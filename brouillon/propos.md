C'est un excellent choix de sujet pour ce projet ! Le scénario de la gestion logistique et du kilométrage des véhicules est parfaitement adapté aux exigences de votre examen. Il va vous permettre de valoriser vos compétences en architecture de données (tables relationnelles, liaisons clés primaires/étrangères), en automatisation de flux et en Business Intelligence.Le fait que vous ayez développé et installé votre propre application mobile pour calculer et remonter la distance parcourue apporte une vraie valeur ajoutée et montre vos compétences opérationnelles.Pour que votre enseignant valide ce thème sans hésitation, voici comment structurer vos spécifications techniques et fonctionnelles.🗺️ Schéma global du flux (Pour votre architecture)Pour ce projet, votre flux de données va suivre une architecture propre (de type Bronze/Silver/Gold) :Source (Bronze) : Votre application mobile calcule la distance et envoie les données (ID Camion, Kilométrage, Date/Heure) vers une base de données intermédiaire ou directement via une API REST.Transformation & Ingestion (Silver) : Un outil d'orchestration (comme un scénario n8n ou un pipeline Apache Hop) récupère ces données quotidiennement, applique les règles de validation, et les insère dans Business Central via son API OData.Valorisation (Gold) : Les données de kilométrage sont croisées avec les données de ventes/expéditions de Business Central (articles transportés, lignes de livraison) pour alimenter vos tableaux de bord (Metabase / Power BI).🗄️ Conception des tables dans Business Central (Modèle de Données)Pour répondre aux critères d'évaluation ("Conception des tables BC de manière professionnelle"), vous allez devoir concevoir l'architecture de vos tables. Pour lier le kilométrage aux articles transportés, il est recommandé de s'appuyer sur quatre tables distinctes pour obtenir une granularité fine :Table Camion (Nouvelle table BC)Code_Camion (Code 20) [PK] : Immatriculation ou ID unique du véhicule.Modele (Text 50) : Modèle du camion (ex: Kia, Toyota).Cout_Au_Km (Decimal) : Coût estimé d'usure/carburant par kilomètre.Table Suivi_Kilometrage (Nouvelle table BC - Alimentée par votre App)ID_Suivi (Integer, AutoIncrement) [PK]Code_Camion (Code 20) [FK] : Lié à la table Camion.Date_Releve (Date) : Date du trajet.Km_Parcourus (Decimal) : Distance envoyée par votre application mobile.Table Entete_Livraison (Sales Shipment Header - Table BC standard ou étendue)No_Livraison (Code 20) [PK] : Numéro du bon de livraison.Code_Camion (Code 20) [FK] : Pour savoir quel camion a effectué la course.Date_Expedition (Date)Table Ligne_Livraison (Sales Shipment Line - Table BC standard ou étendue)No_Livraison (Code 20) [PK][FK]No_Ligne (Integer) [PK]No_Article (Code 20) [FK] : L'article transporté.Quantite (Decimal) : Quantité d'articles dans ce camion.⚡ L'automatisation : Du quasi-temps réel au cycle quotidienLe cahier des charges de l'examen mentionne une récupération "quotidienne". Cependant, pour rendre votre infrastructure robuste et moderne, vous pouvez configurer votre orchestrateur pour travailler sur deux rythmes :Collecte Haute Fréquence (Quasi-temps réel) : Votre application mobile pousse les coordonnées ou les distances vers votre API/Base externe de manière très régulière (avec un cycle court, par exemple toutes les quelques secondes ou minutes pendant le trajet).Traitement & Consolidation (Quotidien) : Chaque fin de journée, un flux automatisé calcule le total quotidien par camion, valide la cohérence des données, et effectue l'importation finale dans Business Central.📊 Proposition pour votre Tableau de Bord (Minimum 3 visuels)Une fois les données croisées dans votre outil BI (installé sur votre machine virtuelle dédiée), vous pourrez concevoir les 3 visualisations obligatoires demandées :Le Graphique Temporel : L'évolution du coût logistique global et des kilomètres parcourus jour après jour ou semaine après semaine.Le KPI Critique : Le coût logistique moyen par kilomètre, ou un taux de conformité (ex: nombre de trajets enregistrés sans erreur d'affectation de camion).Le Tableau Croisé Dynamique (TCD) : Une matrice croisant les Familles d'articles / Produits avec les Coûts logistiques totaux (Calculé ainsi : $\text{Km parcourus} \times \text{Coût au km du camion}$ proratisé selon le volume d'articles transportés). Cela permettra d'analyser précisément la rentabilité par produit.
